# 恶劣天气合成流程总结（雾 / 雨 / 低光，三档强度）

> 用途：把一份干净的 YOLO 检测数据集，合成雾 / 雨 / 低光三种恶劣天气的
> **多强度测试集**，用于检测模型的鲁棒性评估。本文记录完整流程、关键决策、
> 踩过的坑和换数据集的要点，方便以后复用。
>
> 适用场景：手里有干净数据、没有真实恶劣天气数据，需要做"受控退化"的
> 鲁棒性验证实验（训练用干净数据 → 测试用合成天气）。

---

## 一、整体思路

- **只对测试集合成天气**，训练集保持干净。这是"训练分布 vs 测试分布"的
  域偏移实验：模型没见过坏天气，拿坏天气测它看掉多少点。
- **只做像素级退化，不动标注**。三种天气都只改像素，YOLO 标注框坐标不变，
  各档位标注直接复制原图标注。
- **每种天气出 l1/l2/l3 三档**（轻/中/重），得到"性能随强度递增而退化"的
  曲线，而不是单点。这是顶会/严肃期刊的标准做法。
- **雾、雨是深度驱动的**（近清晰、远朦胧），低光是全局的（与距离无关）。

依赖关系：
```
step1 深度估计 (要 GPU, 一次性)
   ├──> step2  雾   (无需 GPU, 用深度算"近淡远浓")
   └──> step2b 雨   (无需 GPU, 用深度算雨雾 veiling)
step3 低光 (无需 GPU, 独立, 不依赖深度)
```

## 二、方法与学术出处

| 天气 | 方法 | 出处（投稿前自行核实标题/年份/venue） |
|------|------|----------|
| 雾 | 大气散射模型 `I = J·t + A·(1-t), t = exp(-β·d)` + 估计深度 | 散射模型(He et al. DCP, CVPR 2009)；深度驱动合成范式 Foggy Cityscapes(Sakaridis et al., IJCV 2018) |
| 雨 | 雨条纹(cv2 画线+运动模糊) + 压暗降饱和 + 深度 veiling | 受 Garg & Nayar "Vision and Rain"(IJCV 2007) 启发的**工程合成**，非其光度学模型的忠实复现 |
| 低光 | 逆 ISP(sRGB→伪RAW) + Poisson-Gaussian 物理噪声 + 提亮放大 | Unprocessing(Brooks et al., CVPR 2019)；SID(CVPR 2018)、ELD(CVPR 2020) |
| 深度 | 单目相对深度估计 | Depth Anything V2 (2024) |

## 三、关键决策与踩坑记录（最重要，换数据集必读）

### 坑 1：视差 → 深度，不要用倒数，用线性反转 ★★★

Depth Anything V2 输出的是**视差**（disparity，近大远小），不是深度。

- 物理上"精确"的做法是取倒数：`depth = 1/disparity`。
- **但在近景主导、带天空的图（如果园、植被特写）上，倒数会崩**：天空视差≈0，
  `1/disp` 爆炸成超大值，归一化后把整个前景碾平成"全部最近"，深度图近乎全黑废图
  （实测近景梯度 std = 0）。
- **最终采用线性反转**：
  ```python
  disp = model.infer_image(img, input_size)          # 视差，近大远小
  d = (disp - disp.min()) / (disp.max() - disp.min()) # 归一化
  d_far = 1.0 - d                                     # 近→0, 远→1
  ```
  它保留了完整的近景相对梯度（std≈0.2），深度图近暗远亮、层次清晰。
  雾合成需要的是**相对远近梯度**，不是米制精确深度，线性反转足够且更稳。

> 结论：理论最优（倒数）≠ 工程可用。**换数据集时，若新数据有大量中远景
> （如街景），倒数可能更合适；若近景主导，用线性反转。务必先抽查深度图！**

### 坑 2：深度方向必须人眼抽查，别只信数值

数值指标（上下半区深度对比）会误导（例如下区全 0 时数值仍"看着对"）。
**一定要把深度图渲染成伪彩色（COLORMAP_INFERNO，亮=远暗=近）和原图并排看**，
确认"近处物体暗、远处/天空亮、层次连续"。

### 坑 3：Depth Anything V2 的安装

- 需要 clone 官方仓库拿 `depth_anything_v2` 包，`pip install` 不一定可靠。
- 国内直连 GitHub 大流量 clone 易 TLS 中断，用镜像前缀：
  `git clone https://ghfast.top/https://github.com/DepthAnything/Depth-Anything-V2.git`
- 权重走 hf-mirror：`https://hf-mirror.com/depth-anything/Depth-Anything-V2-Base/resolve/main/depth_anything_v2_vitb.pth`
- 运行 step1 需 `PYTHONPATH=<repo路径>` 指向含 `depth_anything_v2` 的目录。

### 坑 4：低光噪声要"提亮放大"才符合物理

真实低光：曝光低→信号弱→后期提亮时噪声被放大。所以噪声要在**暗信号域加入后，
再乘一个提亮增益**（`brighten`），这样噪声随之放大，符合 SID/ELD 的场景。
只压暗不提亮，噪声偏弱、不够"脏"。

## 四、三档强度参数（可复现，调参入口都在各脚本顶部 LEVELS）

### 雾 step2（β 控浓度，A 大气光）
| 档 | beta | A | 含义 |
|---|---|---|---|
| fog_l1 | 0.6 | 0.85 | 轻雾/霾 |
| fog_l2 | 1.2 | 0.88 | 中雾 |
| fog_l3 | 2.2 | 0.90 | 浓雾 |
> `MAX_DEPTH_M = 3.0`：把归一化深度放缩成伪米制尺度（拍脑袋常数，影响雾衰减快慢）。

### 雨 step2b
| 档 | drops | length | thickness | darkness | saturation | veil | A |
|---|---|---|---|---|---|---|---|
| rain_l1 | 1500 | 18 | 1 | 0.80 | 0.85 | 0.08 | 0.80 |
| rain_l2 | 2800 | 22 | 1 | 0.68 | 0.72 | 0.14 | 0.82 |
| rain_l3 | 4200 | 28 | 2 | 0.58 | 0.62 | 0.22 | 0.84 |

### 低光 step3
| 档 | ratio | shot | read | brighten |
|---|---|---|---|---|
| lowlight_l1 | 0.30 | 0.010 | 0.010 | 2.0 |
| lowlight_l2 | 0.15 | 0.020 | 0.015 | 3.0 |
| lowlight_l3 | 0.07 | 0.035 | 0.025 | 4.0 |
> 最终相对亮度 ≈ ratio × brighten（保持 <1 仍偏暗），噪声被 brighten 放大。

所有脚本固定随机种子（`np.random.default_rng(0)`），保证可复现。

## 五、目录约定

**输入（干净数据，YOLO 格式）：**
```
<clean_dir>/
  images/*.png
  labels/*.txt       # class cx cy w h，归一化
```

**输出（每种天气按强度分子目录，标注原样复制）：**
```
<out_dir>/
  images/{sunny, fog_l1/l2/l3, rain_l1/l2/l3, lowlight_l1/l2/l3}/*.png
  labels/{同上}/*.txt
```
- `sunny` = 干净原图直接复制，作为晴天基准（算掉点幅度的 100% 分母）。
- 深度图单独放 `<depth_dir>/<图名>.png`（16 位，远=大）。


## 七、换一个新数据集时的检查清单

1. **格式**：先转成 YOLO 格式（images/ + labels/，归一化框）。
2. **深度方案**：跑 step1 后**务必抽查深度图**（第三节坑 1/2）。
   - 近景主导 → 线性反转（当前默认）
   - 中远景丰富（街景等）→ 可改回倒数并加天空百分位裁剪
3. **深度尺度**：`MAX_DEPTH_M` 影响雾的衰减快慢，必要时按场景景深调整。
4. **强度标定**：l1/l2/l3 是**相对梯度**，不是绝对物理标定（如能见度/照度）。
   论文里如实描述为"相对强度递增"，别声称成绝对标定。
5. **抽查合成效果**：雾/雨要"近清晰远朦胧"且 l1<l2<l3；低光要"暗且有噪点"；
   确认目标（检测对象）未被过度遮挡、仍可检测。
6. **sunny 基准**：始终把干净原图复制成 sunny，评估掉点才有分母。

## 八、评估对接（本项目用法，供参考）

- 评估脚本遍历 `WEATHER_ROOT/images/<weather>/`，以 sunny 为基准算
  **掉点幅度 mAP_drop** 和 **保持率 keep(%)**。
- 换天气集只需改配置里的 `WEATHER_ROOT` 和 `WEATHERS` 列表，评估逻辑不用动。
- 输出退化主表：每种天气随强度递增的 mAP 曲线。
